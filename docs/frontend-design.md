# 前端设计与维护约束

修改或新增 UI 时，先阅读同类组件、直接父容器及相关样式。OpenFic 是创作与编辑工具：沿用现有克制、低装饰的视觉模式，不另创一套界面风格。

## 样式归属

- `frontend/src/styles/tokens.css` 管理全局设计值；优先复用其中的字号、字体与语义色，以及 Radix 的颜色、spacing、radius scale。
- Radix props 用于简单结构与标准尺寸；组件旁的 CSS 管理静态视觉、复杂布局和状态样式。不要把同一个属性分散到多套机制中覆盖。
- `frontend/src/styles/utilities.css` 只放确实跨组件复用的通用规则；局部尺寸不要仅为了消除数字而升级成全局 token。
- Inline style 主要用于运行时计算的尺寸、位置等动态值。新增静态颜色、间距、圆角等应归入组件 CSS；状态通常用 class、`data-*` 或 Radix props 表达。
- 优先复用现有值与模式；确需局部特殊尺寸时可以在组件 CSS 使用，不强求所有像素都 token 化。不要借小改动批量改写历史样式。

## 视觉规则

- 灰阶承担主要结构；accent 表达交互焦点，red 表达错误，amber 表达警告。保留已有明确业务状态色，不为装饰添加新颜色。
- 优先通过间距、细边框与轻微背景变化区分层级，不随意增加卡片、阴影和浮层。浮动卡片需检查背景透明度，避免底下的文字穿透。
- 字体、字号、圆角和控件密度沿用现有 token、Radix scale 与同类组件；新视觉模式须有任务要求或具体布局理由。
- 操作图标统一使用 Lucide，不混入 emoji 或另一套图标；已有品牌图标保留其用途。图标按钮应有可访问名称。

## 布局与组件边界

- 修改布局前，读清组件、直接父容器与滚动／定位祖先：谁分配剩余高度，谁滚动，谁占位，谁浮动。不能只依据一个 JSX 片段修改宽高、定位或背景。
- 区分布局容器与视觉表面。全宽 wrapper 可以定位，但背景、border、shadow 应放在真正可见的表面上；浮层不应凭空占据整行高度，透明区域也不应拦截底下的点击。
- 保留 flex 子项需要的 `min-width: 0`、`min-height: 0` 及既有 overflow 边界。检查相邻控件、长内容、折叠状态与窄栏，不能靠固定测试视窗掩盖问题。
- 先找已有组件与所有权边界。按独立职责和接口拆分，不按文件大小机械拆分，也不把巨型组件整体搬成一个巨型 hook。组合层应清楚呈现区块顺序与布局关系。
- 无行为变更的整理要保留 DOM 层级、状态生命周期、事件订阅清理与回调语义；不要混入交互重设计。

## 验证

- 按风险执行格式、类型与相关自动化检查；布局或可见 UI 变化需用 Playwright 打开实际页面并截图检查。独立组件预览不能代替真实宿主页面的布局验收。
- 按影响范围检查编辑页侧栏与讨论页、展开／收起、滚动与相邻浮层；必要时覆盖窄栏和深色主题。不擅自固定或改变用户浏览器视窗大小。
- 不为测试发送真实模型请求或修改正式创作数据；需要可写操作时使用隔离数据或明确标识的浏览器请求模拟，并如实说明验证范围。
- 自动检查不是用户体验验收。报告已验证的行为与未覆盖的部分，将体验交回用户确认。
